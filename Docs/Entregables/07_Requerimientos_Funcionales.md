# Tabla de Requerimientos Funcionales
## Robot SCARA — Sistema de Simulación y Control

| ID | Requerimiento | Descripción | Fuente | Verificación |
|---|---|---|---|---|
| **RF-01** | **Control articular directo** | El sistema debe permitir mover cada articulación (J1, J2, Z, S1, S2) individualmente con comandos desde la interfaz. Los comandos `J:1:θ:v`, `J:2:θ:v`, `J:3:z:v`, `S1:α`, `S2:β` deben transmitirse al ESP32 y actualizar el modelo 3D. | HU-01 | Presionar btn+/− en E1 → observar movimiento en modelo y STATUS recibido |
| **RF-02** | **Cinemática inversa y directa** | El sistema debe calcular IK (posición → ángulos) y FK (ángulos → posición) en tiempo real. El IKSolver debe validar workspace, límites angulares y retornar error descriptivo si la posición no es alcanzable. | HU-02 | Ingresar coordenadas válidas e inválidas en E2 y verificar respuesta visual + mensaje UNREACHABLE |
| **RF-03** | **Comunicación multi-canal** | El sistema debe soportar simultáneamente: (a) USB Serial a 115 200 baud, (b) Bluetooth SPP como COM virtual, (c) TCP Socket en puerto 5005 para Python. Todos los canales deben parsear el mismo protocolo `STATUS:j1,j2,z,x,y,s1,s2`. | HU-07, HU-05 | Conectar por USB, luego por BT, luego abrir Python → verificar cada indicador se pone verde |
| **RF-04** | **Visualización 3D en tiempo real** | El robot 3D debe actualizarse cada frame con interpolación suave (Lerp) de posición. El TCP debe ser marcado con esfera roja y trail de trayectoria naranja. El mapa 2D debe reflejar la posición TCP en el plano XY. | HU-06 | En Play Mode, mover J1 → confirmar pivotArt1 rota y trail dibuja recorrido |
| **RF-05** | **Integración de visión artificial** | El sistema debe recibir coordenadas de objetos desde Python (socket TCP), retransmitirlas al ESP32, actualizar el modelo 3D, mostrar el panel de visión con estado GRAB y mantener historial de los últimos 6 objetos detectados. | HU-05 | Ejecutar vision_compleja.py → verificar en VisionPanel que objeto aparece y GRAB:DONE llega |
| **RF-06** | **Registro y exportación de datos** | El sistema debe registrar automáticamente cada STATUS recibido (DataLogger), permitir exportar CSV con timestamp/ángulos/TCP, y calcular métricas de error (actual, promedio, máximo) comparando FK con objetivo. El ESP32 debe poder exportar su propio log vía CSV_START/CSV/CSV_END. | HU-04, HU-07 | Conectar, mover a posición conocida, presionar "Exportar CSV" → verificar archivo generado con datos correctos |
